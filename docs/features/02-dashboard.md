# 02. 대시보드

**상태**: 구현중 (화면 셸 + API/WS 연동 완료, 자산평가·최근거래·자동매매 상태는 03/07 완료 후 실데이터 연결 예정)
**화면 ID**: SCR-02
**의존성**: `01-auth` (로그인 필요). 자동매매 상태 카드는 `07-auto-trading` 완료 전까지 항상 빈 상태(OFF)로 표시. 최근 거래 내역은 `03-manual-trading` 완료 전까지 빈 목록.
**연관 문서**: [00-overview.md](../00-overview.md) 7장(로드맵 2번 — 셸 우선 구현)

---

## 1. 목적

로그인 직후 기본 진입 화면. 자산 요약, 실시간 시세, 자동매매 상태를 한눈에 보여주는 종합 현황판.

> **구현 순서 메모**: 이 기능은 로드맵상 03(수동매매), 07(자동매매)보다 먼저 오지만 실제 데이터(거래내역, 자동매매 상태)는 그 기능들이 없으면 채울 수 없다. 화면 셸과 API 연동 구조만 먼저 만들고, 데이터 소스가 되는 기능이 완성되는 대로 자연스럽게 채워지는 방식으로 구현한다. 관심 코인 시세(WebSocket)는 자체적으로 완결되므로 바로 구현 가능하다.

레이아웃: 3컬럼 그리드 — 좌: 자산 요약·시세 / 중: 시세 차트·자동매매 상태 / 우: 최근 거래 내역·바로가기

## 2. 화면 구성

### 2-A. 좌측 — 자산 요약 + 주요 코인 시세

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 총 평가금액 카드 | Summary Card | 보유 원화 + 코인 평가금액 합산, **평가손익(전일 대비, %)** 색상 표시. WebSocket 실시간 갱신. 별도 일별 스냅샷 테이블 없이 `Σ(holdings.quantity × 현재가) − Σ(holdings.quantity × 전일종가)` 로 계산하고 전일종가는 `candles(interval='1d')`에서 조회 (원화 잔고는 시세로 변동하지 않으므로 코인 평가액만 비교). 보유 코인이 없으면 0%. 08-portfolio의 "총 손익"(순투입원금 기준 누적)과는 다른 지표이므로 라벨을 구분함 |
| 보유 원화 카드 | Mini Card | `balances.krw_balance` |
| 코인 평가액 카드 | Mini Card | `holdings` 합산 시가 평가 |
| 주요 코인 시세 목록 | List | 관심 코인별 현재가 · 등락률(%), 상승 빨간색/하락 녹색. 헤더의 "+ 추가" 버튼이 관심 코인 추가 진입점(모달 아님, 3장 참고) |
| WebSocket 상태 안내 | Caption | 하단 소형 텍스트 |

### 2-B. 중앙 — 시세 차트 + 자동매매 상태

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 코인 탭 셀렉터 | Tab | 관심 코인 탭만 표시(최대 5개), 선택 상태 유지. 마지막 선택 탭은 저장 컬럼을 두지 않고 **localStorage**에 저장 (스키마 변경 없이 재방문 시 복원). 추가 버튼은 2-A 목록 쪽에만 있어 중복 없음 |
| 일봉 캔들 차트 | Candlestick Chart | 선택 코인의 실 과거 일봉(200개)+거래량. `candles` 테이블(01-erd.md, 원래 03/06 소관)을 앞당겨 구현해 `GET /api/coins/{symbol}/candles?interval=1d`로 조회하고, 당일 봉만 `/ws/prices` 틱으로 실시간 갱신한다. 시간대 탭(1분/10분/30분/1시간)은 넣지 않음 — 03-manual-trading에서 추가 |
| 자동매매 상태 카드 | Status Card | 활성 슬롯이 있으면 슬롯별 요약(전략명+ON 배지+마지막 신호), 없으면 "운용 중인 자동매매 없음" 안내. 클릭 시 SCR-04로 이동 |

### 2-C. 우측 — 최근 거래 내역 + 바로가기

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 최근 거래 내역 목록 | List | 최근 체결 5건, 매수(빨강)/매도(파랑) 배지 |
| 입출금 바로가기 | Chip Button | SCR-07 이동 |
| 알림 설정 바로가기 | Chip Button | SCR-08 알림 섹션 이동 |

> v1.0에 있던 "API 키 설정 바로가기" 칩은 제거됨 (00-overview 6장 원칙 2 — 실 API 키 연동 없음).

## 3. 인터랙션

| 위치 | 이벤트 | 처리 |
|---|---|---|
| 코인 탭 | Click | 선택 코인 1일 시세 갱신, 탭 상태 localStorage 저장 |
| "+ 추가" 버튼 | Click | 버튼 바로 아래 검색 드롭다운 오픈(전체 화면 모달 아님 — 차트를 가리지 않는다). 코인명/심볼 일부 입력 시 후보 최대 8개 표시, 클릭 시 즉시 추가. 최대 5개 제한 |
| 자동매매 상태 카드 | Click | SCR-04 이동 |
| WebSocket 연결 끊김 | System Event | 3회 5초 간격 재연결, 실패 시 배너 |

## 4. 데이터 모델 (추가)

```
watchlists
  id (PK)
  user_id (FK)
  coin_symbol
  sort_order        -- 탭 표시 순서, 최대 5개 제약은 API 레벨에서 검사
```

`총 평가금액`, `코인 평가액`은 별도 테이블 없이 `holdings` × 실시간 시세로 매 요청 시 계산한다.

일봉 캔들 차트를 위해 `candles`([01-erd.md](../01-erd.md) 2장, 원래 03/06 소관)도 이번에 함께 생성했다 — 스키마는 ERD 그대로이며 02는 `interval='1d'`만 사용한다.

## 5. API 엔드포인트 (초안)

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/dashboard/summary` | 총 평가금액/보유원화/코인평가액/평가손익(전일 대비) |
| GET | `/api/watchlist` | 관심 코인 목록 (최대 5개) |
| POST | `/api/watchlist` | 관심 코인 추가 |
| DELETE | `/api/watchlist/{symbol}` | 관심 코인 제거 |
| GET | `/api/dashboard/recent-trades` | 최근 체결 5건 |
| WS | `/ws/prices?symbols=...` | 실시간 시세 구독. 백엔드 시세 캐시에서 요청 심볼만 필터링해 전송 — 백엔드의 Upbit 구독 자체는 이 파라미터와 무관하게 KRW 전체 상시 유지된다 ([00-overview.md](../00-overview.md) 3장) |
| GET | `/api/coins/{symbol}/candles?interval=` | 캔들 조회. [03-manual-trading.md](03-manual-trading.md) 6장에 명세된 경로를 02에서 앞당겨 구현(일봉만 사용) — 03이 그대로 재사용 |
