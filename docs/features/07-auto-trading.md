## 1. 목적

사용자가 설정한 전략을 **서버가 브라우저 접속과 무관하게 상시 실행**하며 자동으로 매매한다. 06에서 검증된 전략 엔진을 실시간 인프라(상시 워커, 잔고 동시성, 알림)에 연결하는 것이 이 기능의 핵심 작업이다.

## 2. 전략 슬롯 구조 (다중 전략 지원)

v1.0의 "전략 선택 = 단일 Radio"는 "전략별 개별 활성화"(FR-A05)와 모순되므로, **전략 슬롯**(코인+전략유형+지표+파라미터+투자금+손절익절+ON/OFF 상태) 단위로 재설계한다.

- 사용자는 "+ 전략 추가"로 여러 슬롯을 등록할 수 있다.
- **제약: 코인 1개당 동시에 활성(ON)인 슬롯은 1개.** 같은 코인에 두 전략이 동시에 신호를 내면 잔고·포지션이 충돌하기 때문. 두 번째 슬롯을 ON 하려 하면 "이미 해당 코인에 활성화된 전략이 있습니다" 안내와 함께 차단.
- 서로 다른 코인에는 서로 다른 전략을 동시에 운용 가능 (예: BTC=RSI 역추세, ETH=그리드).
- `invest_amount`의 전략유형별 의미는 [06-backtesting.md](../06-backtesting.md) 2.4-1절과 동일 (추세추종/역추세는 1회 진입 금액, 그리드/DCA는 전체 배분 상한).

### 2.1 다중 슬롯의 잔고 검증 (신규)

슬롯 하나하나는 "보유 원화 이하"로 검증하지만, 슬롯 A(600만원)+슬롯 B(600만원)를 잔고 1000만원에서 각각 개별 검증만 하면 둘 다 통과해버린다. 이를 막기 위해 두 단계로 검증한다.

- **활성화(ON) 시점 검증**: `(다른 활성 슬롯들의 invest_amount 합) + (이번 슬롯 invest_amount) ≤ 출금 가능액`([01-erd.md](../01-erd.md) 3.1절 — 이미 배정된 슬롯 몫까지 제외한 값). 초과 시 "다른 자동매매에 이미 배정된 금액을 제외하면 잔고가 부족합니다" 안내와 함께 활성화 차단.
- **실행 시점 안전장치**: 검증을 통과했어도 워커가 실제 매수 신호를 처리하는 시점엔 **가용 원화**([01-erd.md](../01-erd.md) 3.1절)가 이미 다른 사유(수동 출금 등)로 줄어 있을 수 있다. 이 경우 해당 매수만 스킵하고 슬롯은 계속 ON을 유지하며 `type=error` 알림을 발송한다 (다음 신호에서 재시도).

## 4. 백엔드 실행 구조

```
자동매매 워커 (상시 프로세스, 예: APScheduler job, tick 주기 10초)
  └─ 매 tick마다 활성(is_active=true) 슬롯 전체 순회
        ├─ [신호 평가 — 확정봉 기준, 중복 방지]
        │     최신 확정봉.opened_at + interval ≤ now
        │       AND 최신 확정봉.opened_at > state.last_evaluated_candle_at
        │       인 경우에만 06의 runner.py로 해당 확정봉 1개 평가
        │       평가 후 state.last_evaluated_candle_at 갱신 (같은 봉 재평가 차단)
        │     DCA는 캔들이 아닌 시간 스케줄: state.dca.next_buy_at ≤ now 로 트리거
        │       (runner.py 인터페이스는 evaluate(slot, candles, now)로 통일 — 06 2.6절)
        │     신호 발생 시:
        │       1) POST /api/orders 내부 호출 (source=auto, strategy_slot_id 기록, 항상 시장가 — 4.1절)
        │       2) notifications 테이블에 이벤트 적재
        │       3) (접속 중이면) 브라우저 푸시 발송
        └─ [손절·익절 — 매 tick 실시간 현재가로 비교, 확정봉을 기다리지 않음]
              보유 포지션(state.position)과 현재가를 매 tick 비교 (2절 표 기준)
```

- 이 워커는 브라우저 세션과 완전히 분리된 백엔드 프로세스다 (00-overview 원칙 1).
- 서버가 재시작되어도 `strategy_slots`에서 `is_active=true`인 슬롯을 다시 로드해 이어서 실행한다.
- **워커는 `state.position`을 직접 갱신하지 않는다.** 워커가 직접 쓰는 것은 `last_evaluated_candle_at`·`grid.lines`의 라인 점유 표시·`dca.next_buy_at` 등 신호 판단용 상태뿐이며, `state.position` 갱신은 체결이 확정되는 [09-execution-engine.md](09-execution-engine.md) 3.2절 체결 후처리 절차가 유일한 주체다.

### 4.1 워커 주문은 항상 시장가

워커가 내는 주문은 지정가를 쓰지 않고 항상 시장가로 처리한다. 신호와 체결 사이의 시차를 최소화하고, pending 상태를 별도로 관리할 필요가 없어 워커 로직이 단순해진다 ([09-execution-engine.md](09-execution-engine.md) 참조).

### 4.2 청산과 포지션 경계 (신규)

자동매매 슬롯은 **자신이 매수한 몫만** 관리 대상으로 삼는다. 같은 코인을 사용자가 수동으로도 보유하고 있을 수 있으므로, 손절·익절·그리드 이탈 청산의 매도 수량은 항상 `min(state.position.quantity, holdings.quantity)`로 상한을 건다 ([01-erd.md](../01-erd.md) 3.6절 `state` 스키마). 수동 보유분은 절대 건드리지 않는다.

- **슬롯 OFF**: `state.position`은 유지한다 (재ON 시 이어서 관리).
- **슬롯 삭제**: 포지션을 인계할 주체가 사라지므로, 삭제 확인 모달에 "이 전략이 보유한 [코인] N개는 수동 보유분으로 남습니다"를 표시한다.

## 5. 03(수동매매)과의 연동 — 코인 단위 잠금

- 슬롯이 ON 되는 순간 해당 코인은 `03-manual-trading`의 주문 패널이 잠긴다 (FR-M10).
- 슬롯이 OFF 되거나 삭제되면 잠금이 해제된다.
- 미체결 주문 취소는 잠금과 무관하게 항상 가능 (자동매매 시작 전 낸 수동 주문 정리용).

## 7. 데이터 모델

> 전체 스키마의 기준은 [01-erd.md](../01-erd.md)다. 아래는 이 기능 관점의 발췌.

```
strategy_slots
  id (PK)
  user_id (FK)
  coin_symbol
  strategy_type       -- trend | counter_trend | grid | dca
  indicator            nullable
  params               jsonb
  invest_amount        -- 의미는 2절 참조 (전략유형별로 다름)
  stop_loss_pct        nullable   -- 2.5절 규칙에 따라 grid/dca는 의미 다름
  take_profit_pct      nullable
  state                jsonb default '{}'   -- 포지션(position)/그리드 체결 라인/DCA 진행상태. 스키마는 01-erd.md 3.6절.
                                              -- 4장 워커 재시작 시나리오 및 8-portfolio 모의투자 초기화 시 함께 리셋되는 값
  is_active            boolean default false
  created_at

  -- 제약: (user_id, coin_symbol) 조합에서 is_active=true 는 최대 1건
```
