## 2. 전략 엔진 설계 (핵심 — 07과 공유)

### 2.1 3단계 선택 구조

```
1단계: 전략 유형   추세추종 / 역추세 / 그리드 / DCA(분할매수)
2단계: 지표        (추세추종·역추세 선택 시만) MA / RSI / MACD / 볼린저 밴드
3단계: 파라미터    지표별 또는 그리드/DCA 전용 파라미터
```

10가지 조합 (추세추종×4 + 역추세×4 + 그리드 + DCA).

### 2.1-1 봉단위 — 공통 설정 항목으로 승격 (신규)

기존에는 봉단위가 지표별 파라미터 안에 흩어져 있었으나, 그리드·DCA는 지표가 없어 봉단위를 입력할 자리가 없었다. **봉단위를 전략 유형과 무관한 최상위 공통 설정**으로 올리고, `backtest_results.params` / `strategy_slots.params` JSONB의 최상위 키 `interval`로 고정한다. 값: `1m` / `10m` / `30m` / `1h` / `1d` ([01-erd.md](../01-erd.md) `candles.interval`과 동일 값 집합).

**봉단위별 최대 조회 기간** (Upbit 캔들 API 1회 200개 제한 + 레이트리밋 하에서 60초 목표(FR-B05, 2026-09 확정 — 최초 30초에서 상향)를 지키기 위한 상한. 어떤 조합도 1만 봉 이내):

| 봉단위 | 최대 기간 | 최대 캔들 수 | Upbit 호출 수(200개/회) |
|---|---|---|---|
| 1분 | 7일 | 10,080 | 51 |
| 10분 | 1개월(30일) | 4,320 | 22 |
| 30분 | 3개월(90일) | 4,320 | 22 |
| 1시간 | 6개월(180일) | 4,320 | 22 |
| 1일 | 5년(1,825일) | 1,825 | 10 |

구현 상수는 `services/candles.py`의 `MAX_RANGE_DAYS`다. "개월"은 30일, "년"은 365일로 환산했다
(`strategy_engine/dca.py`가 매수 주기의 "월"을 30일로 고정한 것과 같은 규칙) — 1시간봉 최대 캔들
수가 설계 당시 4,380으로 적혀 있었으나 180일 기준 4,320이 맞아 정정했다.

**실측(구현 후)**: 가장 무거운 조합인 1분봉 7일이 최초 조회 **13.8초**(51회 호출, 호출당 0.271초),
캐시 적중 시 **0.6초**다. 처음에는 호출마다 TCP+TLS 핸드셰이크를 새로 해 42.8초가 걸렸는데,
HTTP 클라이언트를 재사용하도록 바꿔 3배 이상 줄였다 — 30초 목표(FR-B05)를 지키는 데 이 한 가지가
결정적이었다.

- 기본값: **일봉(`1d`) / 최근 1년**.
- UI: 봉단위 선택 시 시작일 Date Picker의 선택 가능 범위(최소 시작일)를 동적으로 좁힌다. 초과 입력 시 실행 버튼을 비활성화하고 "1분봉은 최대 7일까지 조회할 수 있습니다." 같은 봉단위별 오류 문구를 표시한다 (4장 오류 처리 표에 추가).

### 2.2 전략유형 × 지표 신호 로직

| 지표 | 추세추종 (모멘텀) | 역추세 (평균회귀) |
|---|---|---|
| MA | 골든크로스(단기MA↗장기MA)→매수 / 데드크로스→매도 | 가격이 MA 대비 -X% 이상 이격→매수 / +X% 이상 이격→매도 |
| RSI | RSI 50선 상향 돌파→매수 / 하향 돌파→매도 | RSI≤과매도(기본30)→매수 / RSI≥과매수(기본70)→매도 |
| MACD | MACD선 시그널선 상향 돌파→매수 / 하향 돌파→매도 | MACD 히스토그램 저점 반등→매수 / 고점 하락전환→매도 |
| 볼린저 밴드 | 상단밴드 상향 돌파→매수 / 하단밴드 하향 돌파→매도 | 하단밴드 터치·하회→매수 / 상단밴드 터치·상회→매도 |

**파라미터** (봉단위는 전략유형과 무관한 공통 설정으로 승격됨 — 2.1-1절 참조):
- MA: 단기기간, 장기기간, (역추세) 이격도 기준(%)
- RSI: 기간(기본14), (추세추종)기준선(기본50) / (역추세)과매수(70)·과매도(30)
- MACD: 단기EMA(12), 장기EMA(26), 시그널(9)
- 볼린저밴드: 기간(20), 표준편차 승수(2.0)

### 2.3 그리드 (지표 불필요)

파라미터: **상한가, 하한가, 격자 수**. (기존에 "그리드 간격(%)"도 입력 항목으로 적혀 있었으나, 상한·하한·격자 수가 정해지면 간격은 거기서 따라 나오는 종속값이라 넷 다 자유 입력일 수 없다 — 구현 중 발견해 입력에서 빼고 **파생 표시값**으로 정정. 화면의 전략 미리보기에 "칸당 약 N원 · 하한가 대비 X%"로 계산해 보여준다.)

**격자 구조**: 하한가~상한가를 `격자 수`칸으로 균등 분할하므로 가격 레벨은 `격자 수 + 1`개이고, 그중 **아래쪽 `격자 수`개가 매수 라인**이다. 각 매수 라인의 매도 목표는 바로 한 칸 위 레벨이며, 최상단 라인의 목표가 상한가가 된다.

```
하한가 100 / 상한가 200 / 격자 수 4  →  한 칸 25
  매수 라인 [100, 125, 150, 175]   매도 목표 [125, 150, 175, 200]   라인당 배분 invest_amount / 4
```

- **매수**: 아직 안 채워진 라인 중 `현재가 ≤ 라인가`인 라인 — 가격이 그 라인까지 내려왔다는 뜻이다. 가격이 여러 라인을 한 번에 관통하면 그만큼 여러 라인이 동시에 체결된다.
- **매도**: 이미 채워진 라인 중 `현재가 ≥ 그 라인의 매도 목표`인 라인을 한 칸 위에서 실현한다.
- **하한가 아래에서는 매수하지 않는다** — 범위를 벗어난 구간은 그리드가 다루기로 한 영역이 아니며, 이 방어가 없으면 하한가 밑으로 떨어진 순간 전 라인이 한꺼번에 체결돼 배정액을 다 써버린다.

### 2.4 DCA/분할매수 (지표 불필요)

파라미터: 매수 주기(일/주/월), 회당 매수금액, 종료조건(총 횟수 또는 예산 소진), 추가매수 옵션(직전 매수가 대비 -X% 하락 시 1회 추가매수, ON/OFF).

### 2.4-1 `invest_amount`(투자금)의 의미 — 전략 유형별로 다름

- **추세추종/역추세**: 신호 발생 시 **1회 진입에 사용할 금액**. 진입 후 청산될 때까지 재사용하지 않는다.
- **그리드**: 전체 격자에 배분할 **총 자금 상한**. 격자 수만큼 나눠 각 라인에 배분한다.
- **DCA**: 전체 분할매수 예산의 **총 상한**. "회당 매수금액 × 종료조건(총 횟수)"이 이 값을 넘지 않아야 하며, "예산 소진 시 종료"를 선택하면 이 값 자체가 소진 기준이 된다.

### 2.5 손절·익절 (전략유형별 재정의)

| 전략 유형 | 손절 | 익절 |
|---|---|---|
| 추세추종/역추세 | 진입가 대비 -X% 즉시 청산 | 진입가 대비 +X% 즉시 청산 |
| 그리드 | "그리드 이탈 손절" — 하한가 이탈 시 슬롯 보유분 전량 청산 | 없음 (라인별 개별 실현) |
| DCA | 없음 | "목표 수익률 익절" — 평균매수가 대비 +X% 도달 시 슬롯 보유분 전량 매도 후 전략 종료 |

→ 파라미터 폼과 마찬가지로 손절/익절 입력 필드도 전략 유형에 따라 동적으로 구성이 바뀐다. ("슬롯 보유분"의 의미: 백테스팅은 슬롯=전체 시뮬레이션이므로 실질적으로 전량과 동일하지만, 07-auto-trading에서는 사용자가 같은 코인을 수동으로도 보유할 수 있어 슬롯이 매수한 몫만 청산 대상이 된다 — [01-erd.md](../01-erd.md) 3.6절.)

### 2.6 구현 구조 제안

아래는 **실제 구현된 구성**이다 (07 구현 후 06 Phase A에서 경계를 정리한 결과).

```
backend/app/strategy_engine/
  indicators.py     -- calc_ma, calc_rsi, calc_macd, calc_bollinger (pandas 기반)
  signals.py        -- 전략유형×지표 조합별 매수/매도 신호 함수 (2.2 표 그대로 구현)
  intents.py        -- TradeIntent: 엔진이 호출부에 넘기는 "무엇을 얼마나" 주문 의도
  grid.py           -- 그리드 격자 산술·매매 판정·라인 상태 갱신
  dca.py            -- DCA 스케줄 판정·분할매수 진행 상태 갱신
  exits.py          -- 손절·익절 판정 (2.5절 표를 전략유형별로 분기하는 순수 함수)
  costs.py          -- 체결 비용 계산 공용 함수. 01-erd.md 3.2절 수수료 규칙과 동일 함수를 쓰고
                        백테스팅에서만 슬리피지 항을 추가 적용 (00-overview 6장 원칙 7 — 의도된 비대칭)
                        진입점에서 fee_rate/slippage_rate 컬럼값(% 단위)을 /100 해 소수로 변환한 뒤
                        내부는 전부 소수로 계산 (01-erd.md 3.2절 단위 규칙 — 변환 누락 시 100배 오차)
  runner.py         -- 공통 실행기: evaluate(slot, candles, now, current_price) 인터페이스
                        (백테스팅은 과거 캔들 배열을 통째로 넣고, 07은 확정봉 1개씩 넣는 차이만 있음 — 07-auto-trading.md 4장)
  backtest.py       -- 백테스트 시뮬레이터 (06 전용). 위 함수들을 워커와 같은 순서로 호출한다
  worker.py         -- 상시 워커 (07 전용). 위 함수들을 호출하고 결과를 DB에 기록한다
```

**공유의 경계**: 엔진은 "무엇을 할지"만 정하고(`TradeIntent`), "어떻게 기록할지"는 호출부가 정한다 —
실매매(`worker.py`)는 주문·슬롯 state를 DB에 쓰고, 백테스팅(`backtest.py`)은 메모리 상태를 고친다.
청산 판정(`exits.py`)과 전략 진행 상태 갱신(`grid.mark_line_*`, `dca.advance_after_buy`)까지 엔진에
있으므로, 백테스팅이 실매매 로직을 복제한 곳은 없다. 시뮬레이터가 자체적으로 하는 산술은 **현금
잔고 하나**뿐이다.

### 2.7 백테스팅에만 적용되는 비대칭 (구현 확정)

실체결과 같은 함수를 쓰되, 아래 두 가지는 **의도적으로 다르게** 둔다. 근거 없이 벌어진 괴리와
구분하기 위해 여기 명시한다.

| 항목 | 실매매 | 백테스팅 | 이유 |
|---|---|---|---|
| 슬리피지 | 미적용 | `체결가 = 이론가 × (1 ± 슬리피지율)` | 실체결은 실시세로 체결되므로 더하면 이중 반영 (00-overview 원칙 7) |
| 현금 부족 시 | 그 주문을 **건너뛴다** | 남은 현금만큼 **줄여서 산다** | 실매매의 스킵은 슬롯 배정액 밖의 *사용자 다른 자금*을 지키기 위한 것인데, 백테스트에는 그런 외부 자금이 없다. 백테스트는 초기투자금 = 1회 진입 금액이라 스킵을 그대로 옮기면 왕복 한 번에 수수료만큼만 줄어도 이후 모든 매수가 영구히 스킵돼, 손실 전략이 "거래 2건"으로 끝난다 (구현 중 실측으로 발견) |

**지표 계산 창 제한 (성능)**: 시뮬레이터는 봉마다 `runner.evaluate`를 다시 부르므로, 지표에 넘기는
캔들 창을 **최근 300봉**으로 자른다(`backtest.INDICATOR_LOOKBACK`). 자르지 않으면 비용이 O(n²)이 되어
1분봉 7일(10,080봉) 추세추종/RSI 기준 33.4초로 30초 목표(FR-B05)를 넘겼고, 자르면 13.0초다.
SMA·볼린저는 창 안에서 완결되는 계산이라 결과가 원래 동일하고, RSI·MACD도 기본 파라미터의 20배가
넘는 300봉을 데우고 나면 잔차가 신호를 바꾸지 못한다 — 같은 실측에서 거래 건수와 최종 자산이 창
무제한 실행과 완전히 일치했다.

| 실행 버튼 | Button (Primary) | Progress Bar, 60초(1분) 이내 완료 목표 |
| 결과 저장 | Button (small) + **라벨 입력** (신규) | 기본 라벨 "{전략유형}-{지표}-{코인}-{저장일}" 자동 생성, 수정 가능 |
| 결과 불러오기 | Button (small) | 라벨+저장일+요약수익률 목록 팝업 |

### 3-B. 결과 패널

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 성과 지표 그리드 (7개) | Metric Grid | 총수익률/MDD/승률/Sharpe/거래횟수/최종자산 + **벤치마크 대비 초과수익률**(신규) |
| 수익 곡선 차트 | Line Chart | 매수(빨강)/매도(파랑) 마커, 클릭 시 체결상세 팝업 |
| 전략 비교 카드 | Compare Card | "+ 전략 추가"로 동일 기간·코인 대상 비교 카드 추가 |

**벤치마크 지표**: 동일 기간 해당 코인 단순 보유(Buy & Hold) 수익률 대비 전략 수익률 차이. "그냥 사서 들고 있는 것보다 나은가"를 판단하는 핵심 지표.

**Sharpe Ratio 계산 방법론** (구현 고정값): 무위험수익률 0% 가정, 일간 수익률 평균/표준편차 산출 후 연환산(×√252).
**총 거래 횟수**: 매수 1건 + 매도 1건을 각각 1건으로 카운트 (왕복 세트 아님).

## 5. 데이터 모델

> 전체 스키마의 기준은 [01-erd.md](../01-erd.md)다. 아래는 이 기능 관점의 발췌 (누락돼 있던 `equity_curve`, `backtest_trades`를 ERD 기준으로 보완).

```
backtest_results
  id (PK)
  user_id (FK)
  label
  coin_symbol
  strategy_type        -- trend | counter_trend | grid | dca
  indicator             nullable  -- ma | rsi | macd | bollinger
  params                jsonb     -- 최상위 키 interval 포함 (2.1-1절)
  start_date
  end_date
  initial_capital
  fee_rate
  slippage_rate
  total_return
  mdd
  win_rate
  sharpe_ratio
  trade_count
  final_asset
  benchmark_return
  equity_curve          jsonb     -- [{at, asset}] 시계열, 수익 곡선 차트 렌더링용 (NOT NULL)
                                     -- at은 날짜가 아니라 ISO8601 시각이다(구현 중 정정) —
                                     -- 분봉 백테스트는 하루에 여러 점이 나와 날짜로 접으면 곡선이 뭉개진다
  created_at

backtest_trades         -- 수익 곡선의 매수/매도 마커 클릭 시 조회하는 체결 상세 (FR-B07)
  id (PK)
  backtest_result_id (FK, ON DELETE CASCADE — 결과를 지우면 체결 상세도 함께 사라진다)
  side                  -- buy | sell
  price
  quantity
  profit                nullable  -- 매도 시점 실현손익, 매수 행은 NULL
  executed_at
```
