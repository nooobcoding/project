## 1. 목적

보유 자산 현황, 거래 내역, 성과 분석 리포트를 종합 제공. 별도 테이블 없이 `orders`/`holdings`/`balances`를 집계해서 구성한다.

레이아웃: 상단 4개 요약 카드 / 하단 2컬럼 — 좌(보유자산+거래내역) / 우(도넛차트+성과리포트+초기화)

## 2. 화면 구성

### 2-A. 상단 요약 카드

총 평가금액 / 총 손익 / 수익률 / 보유 원화 — 4개 Metric Card, 실시간 갱신.

**계산식** (미실현 평가손익 포함 — 4장 참조):
- 총 손익 = 총평가금액 − 순투입원금
- 순투입원금 = 초기 시드머니 + Σ입금 − Σ출금
- 수익률 = 총 손익 / 순투입원금 × 100

이 "총 손익"은 `orders.realized_profit`(실현손익만) 합계가 **아니다** — 코인을 들고만 있어서 생기는 평가손익까지 포함한, 사용자가 체감하는 실제 자산 증감이다. 실현손익만 보는 지표는 아래 성과 리포트의 "월별 수익"이다.

### 2-B. 좌측 — 보유 자산 + 거래 내역

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 보유 자산 현황 | Table | 코인별 수량·평균매수가·평가금액·수익률 (`holdings` × 실시간 시세) |
| CSV 내보내기 | Button (outline) | 현재 필터 조건 전체 내역 CSV, 파일명 `trades_YYYYMMDD.csv`. **구현 노트**: 엔드포인트가 GET이라 `<a href>` 직접 링크로는 JWT를 헤더로 실어 보낼 수 없으므로, `fetch`로 Authorization 헤더를 붙여 요청한 뒤 응답을 Blob으로 받아 `URL.createObjectURL`로 다운로드를 트리거한다 |
| **거래 내역 필터 칩** (개정) | Filter Chips | 전체/매수/매도/수동/자동/코인별. **"전체"는 다른 칩과 배타적** — 전체 선택 시 나머지 자동 해제, 다른 칩 선택 시 전체 자동 해제 |
| **코인별 필터** (개정) | Select (검색 가능 드롭다운) | 칩이 아닌 드롭다운으로 변경. 실제 거래한 적 있는 코인만 노출 (전체 상장 코인 아님) |
| 거래 내역 목록 | Table | 유형 배지+자동 배지+코인명+체결가+수량+체결일시 |
| 페이지네이션 | Pagination | 20건/페이지 |

### 2-C. 우측 — 자산 배분 + 성과 리포트 + 초기화

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 자산 배분 도넛 차트 | Donut Chart | 코인별 비중 (원화 포함) |
| 성과 분석 리포트 | Info Card | 기간/가장 많이 거래한 코인/월별 수익 |
| 모의투자 초기화 | Button (danger) + Modal | 확인 다이얼로그 후 `01-auth`와 동일한 초기 시드머니로 리셋. **활성 자동매매 슬롯이 있으면 함께 강제 OFF** — 다이얼로그 문구에 "진행 중인 자동매매도 함께 중지됩니다" 포함 |

## 3. 인터랙션 / 오류 처리

| 위치 | 이벤트 | 처리 |
|---|---|---|
| 필터 칩 클릭 | Click | 배타 로직 적용 후 목록 재조회, 페이지 1로 초기화 |
| 코인별 드롭다운 선택 | Change | 목록 재조회 |
| CSV 내보내기 | Click | 필터 조건대로 서버에서 생성 후 다운로드 |
| 도넛 차트 섹터 클릭 | Click | 해당 코인 상세 강조 |
| 모의투자 초기화 확인 | Click | `orders`/`holdings`/`deposits_withdrawals` 삭제 → **활성 `strategy_slots` 전부 OFF 전환 + `state` 리셋** → `balances`를 시드머니 값으로 리셋 → 새로고침 (순서 중요: 슬롯을 먼저 꺼야 초기화 도중 워커가 매매를 시도하지 않는다) |

| 오류 상황 | 메시지 |
|---|---|
| CSV 생성 실패 | 파일 생성 중 오류가 발생했습니다. 다시 시도해주세요. |
| 거래 내역 없음 | 해당 조건의 거래 내역이 없습니다. |

## 4. 데이터 모델

신규 테이블 없음. `orders` + `holdings` + `balances` + `deposits_withdrawals`를 조회 시점에 집계한다. 전체 스키마 기준은 [01-erd.md](../01-erd.md).

**월별 수익(FR-P04)**: `orders.realized_profit`(매도 체결 시 기록되는 실현손익, [01-erd.md](../01-erd.md) 참조)을 `filled_at` 기준 월별로 `SUM`해서 산출한다. 시세 변동에 따른 미실현 평가손익은 포함하지 않는다.

## 5. API 엔드포인트 (초안)

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/portfolio/summary` | 총평가금액/총손익/수익률/보유원화 |
| GET | `/api/portfolio/holdings` | 보유 자산 테이블 |
| GET | `/api/portfolio/allocation` | 도넛 차트용 비중 데이터 |
| GET | `/api/portfolio/trades?type=&source=&coin=&page=` | 거래 내역 (필터 배타 로직은 프론트에서 쿼리 조합) |
| GET | `/api/portfolio/trades/export` | CSV 다운로드 |
| GET | `/api/portfolio/report?period=` | 성과 분석 리포트 |
| POST | `/api/portfolio/reset` | 모의투자 초기화 |
