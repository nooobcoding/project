## 1. 목적

보유 자산 현황, 거래 내역, 성과 분석 리포트를 종합 제공. 별도 테이블 없이 `orders`/`holdings`/`balances`를 집계해서 구성한다.

레이아웃: 상단 4개 요약 카드 / 하단 2컬럼 — 좌(보유자산+거래내역) / 우(도넛차트+성과리포트)

## 2. 화면 구성

### 2-A. 상단 요약 카드

총 평가금액 / 총 손익 / 수익률 / 보유 원화 — 4개 Metric Card, 실시간 갱신.

**계산식** (미실현 평가손익 포함 — 4장 참조):
- 총 손익 = 총평가금액 − 순투입원금
- 순투입원금 = 초기 시드머니 + Σ입금 − Σ출금
- 수익률 = 총 손익 / 순투입원금 × 100

이 "총 손익"은 `orders.realized_profit`(실현손익만) 합계가 **아니다** — 코인을 들고만 있어서 생기는 평가손익까지 포함한, 사용자가 체감하는 실제 자산 증감이다. 실현손익만 보는 지표는 아래 성과 리포트의 "월별 수익"이다.

### 2-B. 좌측 — 보유 자산 + 거래 내역

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 보유 자산 현황 | Table | 코인별 수량·평균매수가·평가금액·수익률 (`holdings` × 실시간 시세) |
| CSV 내보내기 | Button (outline) | 현재 필터 조건 전체 내역 CSV, 파일명 `trades_YYYYMMDD.csv`. **구현 노트**: 엔드포인트가 GET이라 `<a href>` 직접 링크로는 JWT를 헤더로 실어 보낼 수 없으므로, `fetch`로 Authorization 헤더를 붙여 요청한 뒤 응답을 Blob으로 받아 `URL.createObjectURL`로 다운로드를 트리거한다 |
| **거래 내역 필터 칩** (개정) | Filter Chips | 전체/매수/매도/수동/자동/코인별. **"전체"는 다른 칩과 배타적** — 전체 선택 시 나머지 자동 해제, 다른 칩 선택 시 전체 자동 해제 |
| **코인별 필터** (개정) | Select (검색 가능 드롭다운) | 칩이 아닌 드롭다운으로 변경. 실제 거래한 적 있는 코인만 노출 (전체 상장 코인 아님) |
| 거래 내역 목록 | Table | 유형 배지+자동 배지+코인명+체결가+수량+체결일시 |
| 페이지네이션 | Pagination | 20건/페이지 |

### 2-C. 우측 — 자산 배분 + 성과 리포트

| 컴포넌트 | 유형 | 설명 |
|---|---|---|
| 자산 배분 도넛 차트 | Donut Chart | 코인별 비중 (원화 포함). **별도 API를 두지 않는다** — 보유자산 목록 응답과 보유 원화로 화면에서 파생시킨다. 화면이 실시간 시세로 평가금액을 재계산하므로, 서버가 따로 계산해 내려주면 표와 도넛의 숫자가 어긋난다 |
| 성과 분석 리포트 | Info Card | 기간 셀렉트(1개월/3개월/6개월/1년/전체) + 가장 많이 거래한 코인 + 월별 수익. 기간을 바꾸면 리포트 전체가 그 기간 기준으로 재계산된다 |

## 4. 데이터 모델

신규 테이블 없음. `orders` + `holdings` + `balances` + `deposits_withdrawals`를 조회 시점에 집계한다. 전체 스키마 기준은 [01-erd.md](../01-erd.md).

**월별 수익(FR-P04)**: `orders.realized_profit`(매도 체결 시 기록되는 실현손익, [01-erd.md](../01-erd.md) 참조)을 `filled_at` 기준 월별로 `SUM`해서 산출한다. 시세 변동에 따른 미실현 평가손익은 포함하지 않는다.

## 5. API 엔드포인트

| Method | Path | 설명 |
|---|---|---|
| GET | `/api/portfolio/summary` | 보유원화 + 코인 평가금액 + 순투입원금. **총손익·수익률은 서버가 계산하지 않는다** — 화면이 실시간 시세로 평가금액을 재계산하므로 `총손익 = 총평가금액 − 순투입원금`은 프론트에서 낸다 |
| GET | `/api/portfolio/holdings` | 보유 자산 테이블 (도넛 차트도 이 응답에서 파생) |
| GET | `/api/portfolio/trades?side=&source=&coin_symbol=&page=` | 거래 내역 (필터 배타 로직은 프론트에서 쿼리 조합). 응답에 `traded_coins`(코인 드롭다운 목록)를 함께 담는다 — 목록이 페이지네이션돼 있어 프론트가 현재 페이지만으로는 전체 코인을 알 수 없기 때문이며, **코인 필터를 뺀 나머지 조건 기준**으로 뽑아야 코인을 고른 뒤에도 드롭다운이 한 개로 쪼그라들지 않는다 |
| GET | `/api/portfolio/trades/export` | CSV 다운로드 (`/trades`와 같은 필터, 페이지네이션 없이 전체) |
| GET | `/api/portfolio/report?period=` | 성과 분석 리포트 (`period` ∈ `1m`/`3m`/`6m`/`1y`/`all`) |

### FR-P05(모의투자 초기화) 제외 사유

사용자가 자기 계정의 거래 데이터를 스스로 전부 지우는 self-service 초기화는 프로젝트 방향과 맞지 않는다고 판단해 08에서 구현하지 않는다. 초기화는 성격상 관리자 기능에 가까우므로, 추후 관리자 기능을 별도로 설계할 때 "관리자가 대상 유저를 초기화"하는 형태로 다시 검토한다 — 그 경우 대상 `user_id` 파라미터와 권한 검사가 필요하므로 여기서 계획했던 self-service 엔드포인트(`POST /api/portfolio/reset`)와는 다른 설계가 된다.

이 결정으로 함께 보류된 것: [01-erd.md](../01-erd.md) 3.4절의 초기화 처리 순서, `strategy_slots.state`를 `{}`로 리셋하는 유일한 경로.
